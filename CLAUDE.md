# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`daisybio/domainsplit` is an nf-core-flavored Nextflow DSL2 pipeline (template v4.0.2, but `is_nfcore: false`) that builds a SQLite database of domain-domain interactions (`domainsplit.sqlite3`) from public + manually-supplied sources (3did, HIPPIE, PPIDM, Negatome, a Y2H/MS negative-PPI screen, UniProt, STRING, Pfam, pfam2go), enriches it with GO terms, protein sequences and STRING PPIs, then carves it into one database per (splitting strategy, split). Embeddings are **not** in the database: every domain instance is embedded with ProtT5 + ESM3/ESMC and published as three HDF5 files under `embeddings/`. The master carries no BLOBs.

Splitting and negative sampling are **delegated to `ppi-splitting-pipeline`**, imported as a git submodule at `subworkflows/external/ppi-splitting` and called as the `PPI_SPLITTING` named workflow with three dataset rows (`random`, `minimal_leakage`, `external_test`). The two ILP rows each ask for two negative sets (`ilp` + `ilp_candidates`) and `random` asks for three (`uniform` + both ILP sets → `random`, `random_ilp`, `random_hrni`), so three rows yield **7 method directories / 26 split databases**. `reports/run_manifest.json` (`WRITE_RUN_MANIFEST`) records params, git commits, manual-input SHA-256s, URL headers (a `url_*` given as a local path is staged and SHA-256-hashed instead of HEADed) and per-split positive/negative counts. `PLAN_ppi_splitting_integration.md` is the spec for that integration and the record of what is and is not wired; read it before changing anything in that path.

## Running the pipeline

Standard invocations (`nextflow run . -profile test,docker`, `nf-test test`, `nf-core pipelines lint`, `pre-commit run --all-files`, `nf-core modules install`) work as expected. Two non-obvious rules:

- **Pass pipeline parameters via CLI flags or `-params-file` only.** Per nf-core convention, parameters MUST NOT be set in `-c` config files — only process/executor config goes there.
- `conf/test.config` fixtures are meant for `-stub` runs (see `tests/default.nf.test`): process bodies never execute, so those tests verify DAG wiring (channel topology, split fan-out, publish paths) and nothing about per-module logic. **That test currently cannot run**: `-stub` silently falls back to the real `script:` block for a process with no `stub:` block, and no ppi-splitting process defines one. `nextflow run . -profile test -preview` is the working DAG check meanwhile (pass `--gurobi_license <any existing file>`, otherwise it stops at the missing local `gurobi.lic`; with it the preview exits 0 and the wiring tests assert that). The `output {}` block in `main.nf` is `enabled !workflow.preview`: otherwise Nextflow's on-complete output summary waits forever on a publish that never runs, and the preview never exits.
- Add `NXF_OFFLINE=1` locally, or the `nfcore_custom.config` fetch times out and config parsing fails.
- `conf/test_full.config` is still an unmodified nf-core template placeholder — not usable as-is.

## Gotchas

- **Everything is a value channel** (a single SQLite path) flowing between processes, NOT a per-sample samplesheet. The `samplesheet` channel from `PIPELINE_INITIALISATION` is wired in but `DOMAINSPLIT` ignores it — input comes entirely from `params.url_*`. Don't reshape `domainsplit_db` channels into meta-tuple channels without updating every downstream consumer.
- **One manual input is left: `negative_ppi_parquet`** (no download automation, no documented provenance). HIPPIE comes from `url_hippie` and PPIDM is computed in-pipeline (the legacy `ppidm_tsv` replaces the computed positives when set, and then any `INVERSE_PPIDM*` token is refused). Every `url_*` param takes a URL or a local path (Nextflow `file()` stages either; `url_negatome` is the exception for URLs only, which go through `DOWNLOAD_NEGATOME` because the default host's TLS chain lacks an intermediate and needs its unverified-cert fallback). `COLLECT_DDI_DATA` fetches and parses only the external sources `--external_test_sources` selects (empty = all), so e.g. `negatome` alone never downloads a PPI file.
- **PPIDM / INVERSE_PPIDM are computed in-pipeline** (`EXTRACT_PPI_MITAB` → `BUILD_PPIDM_SOURCES` → `COMPUTE_PPIDM`, `PLAN_ppidm_in_pipeline.md`), and the default external test set is `PPIDM_Gold` vs `INVERSE_PPIDM_Gold` with `--external_test_balance uniform` (homo pairs dropped, larger class subsampled, seeded; a one-class selection needs `none`). Three things are deliberate and easy to "fix" wrongly: (1) `K` counts only PPIs with `x` on one protein and `y` on the other — both reference code bases count same-protein co-occurrence, which makes every homo pair significant; (2) Gold is the **published code's** rule (significant in ≥ ceil(S/2) sources), not the paper text's, which collapses Gold to ~250 pairs; (3) the accession→Pfam map is `ppidm_uniprot_dat` (all-species Swiss-Prot), **never** `PARSE_SWISSPROT`'s tier-filtered one, so the labels are identical in every `instance_tier` and only `BUILD_EXTERNAL_TEST`'s instance check differs. Confidence cutoffs apply to the positive side only; filtering the negative side manufactures missing co-occurrences. `reports/ppidm/` holds the labels' statistics and `ppidm_report.json`; an INVERSE pair that 3did holds shows up in `source_conflicts.tsv` as `dropped_protected_label_conflict`, which is the measured false-negative floor. A pair whose two domains share any universe protein is never INVERSE (`inverse_excluded_same_protein` in `ppidm_report.json`): cross-protein `K` cannot see an intra-chain contact, while `n(x)`, `n(y)` do. Explicit `PPIDM_<Class>`/`INVERSE_PPIDM_<Class>` tokens narrow `ppidm_classes` per side (`ppidmParseClasses` in `collect_ddi_data`) **only when every selected token is a PPIDM one** (the two are disjoint by construction), so an unselected class reaches neither the master DB nor the family union. Next to `negatome` or `single_domain_ppi`, or with a bare `PPIDM`/`INVERSE_PPIDM` token or an empty selection, every configured class is parsed — an unparsed class would hide an external label conflict from `INSERT_EXTERNAL_SOURCES`. Classes compare case-insensitively; a requested class missing from `ppidm_classes` fails at startup. A one-label explicit selection under `--external_test_balance uniform` fails at startup.
- Split DBs publish to `databases/<method>/<split>.sqlite3` (see the `output:` block in `main.nf`); domain embeddings publish to `embeddings/<model>_domain_embeddings.h5` via a `withName` rule in `conf/modules.config`. An `EXPORT_*`/`GENERATE_*` process without such a rule publishes to a directory tokenized from its own name, which is how a mis-routed file appears. The README still carries unfilled nf-core template TODOs (intro summary, workflow figure, step bullets).
- **`esm3_structure` is opt-in** (add it to `--embedding_models_domainbench`; a fourth H5). Its coordinates are **AlphaFold DB monomers, not PDB**: UniProt-numbered (no alignment), near-uniform coverage — PDB coverage tracks how well-studied a protein is, which differs by label (the F11 leak) — and no partner conformation. `FETCH_AFDB_STRUCTURES` (CPU, runs only when the model is requested) caches `AF-<acc>-F1-model_v<afdb_version>.pdb.gz` under `cache_dir/afdb-v<N>/`, drops a protein whose model disagrees with this run's UniProt sequence above `afdb_max_mismatch_rate`, NaNs residues below `afdb_min_plddt`, and writes per-accession `(L,37,3)`; the GPU task only reads that H5. AFDB serves only its latest version (v4/v5 files 404), so bumping `afdb_version` is a forced, not an optional, change. ESM3 runs at batch 1, so the structure/SS8/SASA tracks are never padded and `_stack_batch` refuses a batch that carries them.
- `HF_TOKEN` (HuggingFace, for the gated ESM3/ESMC weights) is required via `.env` / `nextflow secrets` — see `.env.example`. ProtT5 is ungated and needs no token.
- The UniProt flat files in `uniprot_dat_urls` feed **five** consumers: GO terms, the accession→Pfam map, the protein FASTA, the STRING-id map (`DR STRING;`, which replaced the per-organism `url_uniprot_id_mapping` download) and `FETCH_DOMAIN_META`'s protein universe. `--dat` is repeatable and **Swiss-Prot must be listed first** — an accession promoted from TrEMBL to Swiss-Prot between releases is in both files and both parsers take the first writer. The accession→Pfam map is written for **reviewed entries only** (`--pfam-map-reviewed-only`, default on): it (`swissprot_pfam.tsv.gz`, `Entry\tPfam`) is read directly by `parse_single_domain_ppi.py`, which infers a DDI from a HIPPIE PPI between two _single-domain_ proteins, and on a TrEMBL entry "exactly one domain" is not a claim an automatic annotation over a possible fragment can support. HIPPIE is read by **UniProt accession only**; a file without `uniprot_accession_A/B` columns is rejected rather than silently yielding zero DDIs.
- `domain.id` is a surrogate integer, so **nothing published keys on it**. The embedding HDF5s key on the Pfam accession (`h5[pfam_id][instance_id]`, `domain` is `UNIQUE(pfam_id)` so the two are 1:1), and carry no run identifier — accession keys need no cross-run guard. Anything new that leaves this pipeline must key on `pfam_id` too — a surrogate id crossing the boundary resolves to the wrong row in another run instead of failing.
- **`instance_tier` is the protein universe, and three params are derived from it.** One knob, four alternatives (not a ladder): `human_reviewed` (default, ~20 k entries), `all_species_reviewed` (~573 k), `human_any_review_status` (~200 k) and `all_species_any_review_status`, which **hard-fails** — it needs the 110 GB TrEMBL file and `FETCH_DOMAIN_META` parses the universe into an in-memory dict (daisybio/domainsplit#4). From it come `uniprot_dat_urls` (which files are downloaded), `swissprot_taxon_ids` (which taxa survive parsing) and `instance_tiers` (ppi-splitting's stratum-name list).
  - **The derivation lives in `nextflow.config`, not in the workflow**, because `FETCH_DOMAIN_META` is in the read-only submodule and reads `params.instance_tiers` from its own script block, and `params` is read-only by the time a workflow body runs. A CLI `--instance_tier X` _is_ visible to the config — Nextflow merges command-line params into the binding before parsing it — which is what makes that work; each derived value guards on `!= null`, not truthiness, so an explicitly empty value survives. `tests/python/test_instance_tier_wiring.py` pins this.
  - `instance_tier` → `instance_tiers` is **the only place the two vocabularies meet**. Upstream has no notion of `human_any_review_status`; this repo has no notion of `other_reviewed`.
  - Upstream fills strata in the order `human_reviewed → other_reviewed → human_unreviewed → other_unreviewed`: **reviewed outranks human**. Lower strata fill _freely_, not as a top-up, so widening the universe reshapes the instance pool of families that were never dropped — only `human_reviewed` reproduces the previous run's numbers.
  - The retired vocabulary is `human_only` (→ `human_reviewed`) and `any` (→ `all_species_reviewed`, **not** `all_species_any_review_status`). Both are rejected with the mapping rather than aliased, because aliasing `any` would silently change the universe of a working invocation.
  - `ingest_instances.py` asserts the taxon invariant at the other end; `protein.reviewed` (from `instances.tsv`'s `source_db`) and `protein.taxon_id` make the result stratifiable, and `reports/ddi_tier_breakdown.tsv` counts surviving DDIs per stratum — a DDI above `human_reviewed` is one a narrower universe would have pruned.
- **Domain instances come from `Pfam-A.regions.tsv.gz`, never `Pfam-A.fasta`.** Pfam publishes the FASTA 90 % non-redundant, which drops the human member of every well-conserved family — a 12,769-family human request kept only 2,140. The regions file has no redundancy reduction; it carries coordinates only, so the UniProt flat files supply sequence (`SQ`), taxon (`OX`) and the review flag (the `ID` line's `Reviewed;`/`Unreviewed;` token). That fix lives in the submodule's `bin/fetch_domains.py`.
- **STRING is fetched per organism, never as the monolith.** `protein.links.v12.0.txt.gz` (all organisms) is 138 GB and >99 % irrelevant, so `FETCH_STRING_LINKS` downloads `<taxid>.protein.links.v<rel>.txt.gz` per taxon and drops every edge whose endpoints are not both in this run's `protein` table — `insert_ppi.py` therefore sees a small file and streams it. **The taxon list comes from the STRING id prefixes (`9606.ENSP…`), not from `protein.taxon_id`**: UniProt's `OX` can be strain-level with no STRING file, while the prefix is STRING's own species id, so the join is exact by construction. A 404 per taxon is counted in `reports/string_taxa_report.tsv`, never fatal; _every_ taxon 404ing is. Setting `url_string` pins one explicit links file and skips the fetch, which is how `-profile test` stays offline. **TrEMBL proteins get no PPI enrichment and no links file changes that** — UniProt does not cross-reference STRING for unreviewed entries (measured: 4,616 `uniprot_trembl_human` entries carried 15 `DR STRING;` lines), so both parsers report the gap rather than leaving it to be re-investigated. **`score` is `REAL` in the schema and `float()`-parsed on insert**, and a non-numeric third field is fatal in `insert_ppi.py`. Both halves are needed and both were missing: the column used to be declared typeless (BLOB affinity, no conversion) while the streaming rewrite bound `parts[2]` verbatim — the earlier `pd.read_csv` version had parsed it — so `score` reached consumers as TEXT `'400'` and domainbenchmark's confidence filter raised `'>=' not supported between instances of 'str' and 'int'` mid-run. Same failure mode as the `start_pos`/`end_pos` affinity note in `INIT_DOMAINSPLIT_DB`.
- **One cache root: `cache_dir`.** ppi-splitting's Pfam/UniProt downloads land under `pfam-<release>/` and the per-organism STRING files under `string/`. `interpro_cache` is ppi-splitting's own name for it and is kept as a legacy alias — `nextflow.config` sets one from the other, `cache_dir` wins.
- **An empty off-switch must be passed as `--x=`, never `--x ''`.** Nextflow 26 parses `--x ''` as the String `"true"`, so `--structure_data_methods=`, `--embedding_models_domainbench=`, `--external_test_sources=` and `--swissprot_taxon_ids=` (or a `-params-file`) are the working forms; `rejectBareFlag` in `workflows/domainsplit.nf` fails the `"true"` case with that hint.
- **A boolean param cannot be tested for truthiness directly.** A CLI `--flag false` arrives as the String `"false"`, which is truthy in Groovy, so `params.flag ? a : b` silently takes the `a` branch. Use `params.flag.toString().toBoolean()`. This bit `ppi_splitting_multi_negset` and `embedding_require_gpu`, both of which are documented off-switches.
- **Structure (ENRICH_STRUCTURAL → ANNOTATE_DDI) runs on the master before SUBSET_SPLIT_DB**, for the methods in `structure_data_methods` (`all` default, empty = off, which also means `af_metadata` is never opened). The AF model index (`BUILD_AF_METADATA`, below) does **not** cover every protein pair; `source` `downloaded` is higher confidence than `inferred`. The complex files are read from paths _inside_ that CSV, so they are not staged by Nextflow (only the stat fingerprint columns of `af_metadata.csv` make a changed model or sidecar invalidate `-resume`, and containers must see the paths). `has_structure` (default 0) is per instance pair; `z_score` is per (method, instance pair), scored once and copied to every split row, with draws seeded from `seed` + the pair key. Each method's contact potential comes from **its own train positives only** — anything else leaks test DDIs into the background. Train rows are scored **cross-fit**: `ddi_fold(seed, ddi_id)` (5 folds, CRC32, grouped by `ddi_id`) splits the train positives, `BUILD_SCORING_MATRIX` counts per fold, `MERGE_SCORING_MATRIX` writes `<method>.fold_counts.json` next to the all-fold potential, and `SCORE_DDI` scores a train row with the potential minus its own fold, a val/test row with the full one — otherwise a train positive's own contacts inflate its score. Train membership is per **instance pair**, not per `ddi_id`, so a val/test pair of a DDI that also has a train pair gets the full potential. A pair whose random trials are constant (`np.ptp == 0`, a sparse potential) stays unscored (`z_score` NULL, no vote), never 0. `ENRICH_STRUCTURAL_AF` slices a pair only if each window matches `protein.sequence` by residue number (mismatch rate <= `afdb_max_mismatch_rate`, >= 80 % of the window validated, insertion-coded residues never count); otherwise `has_structure` stays 0. Both are model features, so coverage differing between labels is a label leak: `tests/bin/dataset_audit_queries.py` F11 measures it.
- **`drop_homomer_ddi` (default false) removes same-family DDIs in two places**: `EXPORT_SPLIT_DDIS` keeps 3did homomers out of `PPI_SPLITTING`, and `PRUNE_UNREPRESENTED_DDIS` deletes every remaining one (sampled negatives, external sources; reason `homomer` in `pruned_ddis.tsv`). It also forces `neg_ilp_lambda_self_loop` to 0 in `metaOf`, because upstream's large-scale ILP sampler force-keeps a self-pair negative per family whenever that weight is > 0. Upstream samplers can still draw self-pair negatives, which are dropped after sampling, so a split can end up with slightly fewer negatives than positives.
- **AF models come from `BUILD_AF_METADATA`, never a hand-merged CSV.** `--af_downloaded_manifest`, `--af_inferred_dirs` (scanned in place on every run) and/or `--af_metadata` are merged by `bin/build_af_metadata.py`: written from scratch, missing models dropped, exact repeats once, two different models of one source for one unordered pair fatal, `downloaded` beats `inferred`. A job dir is `<prefix>_<acc>_<acc>/<same>_model.cif` with UniProt-shaped accessions; the prefix (`Pos_` for every pair by the AF3 builder's default) is never a label. `SCAN_AF_METADATA` is `cache false` and only emits a digest (plus the published inventory/report); `BUILD_AF_METADATA` is cached on that digest so an unchanged scan keeps `ENRICH_STRUCTURAL_AF` cached. Do not make the build uncached: its work-dir path is part of the slicer's cache key.
- **Two structure steps sit around ANNOTATE_DDI and read different states.** `BUILD_AF3_QUEUE` (AF3 queue, `structures/af3_to_model/queue.tsv`) reads the master straight after `ENRICH_STRUCTURAL_AF`; `STRUCTURE_COVERAGE_BALANCE` runs after scoring and masks `has_structure`/`z_score` per (method, split) (whole split masked below `structure_min_coverage`, otherwise the better-covered label down to the other's fraction). So the contact potential still sees every train positive, `has_structure_raw` keeps the unmasked value, and `structure_coverage.tsv` / `af3_to_model/` describe the unmasked state. Do not move the queue after the guard: a pair whose slices were all masked would be misreported as an unusable model. Queue levels live in `LEVELS` in `bin/build_af3_queue.py`; a new split must be added there or the run fails.
- **Enrichment metadata is per method** (`metadata/<method>/{domain,ddi}_metadata.csv`, domainbenchmark's `--metadata`). domainbenchmark reads one metadata directory for every database and filters by instance pair, while the guard masks per (method, split), so one run-wide file would hand masked pairs their `af_*` values. `EXPORT_DDI_METADATA` reads the master **after** the guard and keeps a pair for a method only if all of that method's rows of it have `has_structure = 1`; do not move it before the guard. It scores from `structures.h5` alone (slice PDB + PAE block, rows mapped by the `residues_a`/`residues_b` attrs, chains by name because a swapped slice lists chain B first). `EXPORT_DOMAIN_METADATA` needs no structure and reads the pre-structure master. Column names (`af_` prefix, `isoelectric_point`) are keyed on by domainbenchmark and the thesis plots.
- **Frozen splits** (`frozen_splits/`, `--frozen_splits`): a bundle of ppi-splitting's split CSVs plus FETCH_DOMAIN_META's outputs, gated three times (launch params/split set, `VERIFY_FROZEN_SPLITS` before ingest, `CHECK_FROZEN_DB` on membership + protein fingerprints before structure/subset). Both gates are `cache false` on purpose. Adding a param that changes instances, splits or external test membership means adding it to `frozenParamKeys()`.
- Some processes shell out to `bin/mysql2sqlite` (vendored awk script) — keep `bin/` executable.
- Test coverage is thin: a handful of pytest files in `tests/python/` over individual `bin/` scripts, plus stub-only nf-test DAG wiring. Most modules have no unit tests. `tests/python/test_instance_tier_wiring.py` is the exception that shells out to `nextflow run -preview`; it skips when `nextflow` is not on PATH.

## Conventions

- Module imports: `include { NAME } from '../modules/local/<dir>/main.nf'`. Local subworkflow files are referenced via `./subworkflows/...` **relative to `workflows/domainsplit.nf`, NOT the project root**.
- nf-core modules are installed via `nf-core modules install` and tracked in `modules.json`; don't hand-edit them — override behavior with `ext.args` in `conf/modules.config`. Only nf-core _subworkflows_ are installed at the moment; `modules/nf-core/` is empty.
- **`subworkflows/external/ppi-splitting/` is read-only. The only permitted operation is pulling the current pushed version** (`git fetch` + fast-forward to `origin/domain_split`, leaving the submodule on that branch). No file edits, no local commits, no patches, not even temporary ones. When something in that pipeline needs to change, say what the change is and stop — the user makes it in `~/Programming/ppi-splitting-pipeline`, pushes, and then it is pulled here. A local edit is invisible upstream, is destroyed by the next pull, and its `bin/` is baked into the Docker image, so it produces a silently _wrong_ run rather than a failure. Bumping the pin shows up in this repo as `M subworkflows/external/ppi-splitting`, which looks like a content edit — say explicitly that only the pointer moved, and report the commit id.
- Nextflow reads only the root project's `nextflow.config`, so that pipeline's params come in via `includeConfig` of its `conf/params.config` and everything else it needs (container, per-process resources, the `gurobi` label, publishing) is restated in `conf/ppi_splitting.config`. Its `bin/` is baked into its Docker image, so the image tag and the submodule pin move together.
- **Package pins live only in `docker/env/{general,gpu}.yml`.** The Dockerfiles `micromamba create -f` them (build context `docker/`), and every `modules/local/**/environment.yml` is a symlink to one of them, so conda and container runs share pins. Change a version there, then bump the image tag in every `main.nf` `container` line. GPU ceiling is esm's torch pin, not the driver.
- `conf/modules.config` is also where `publishDir` lives; the default path tokenizes the process name (`${process.split(':').last().split('_').first().lowercase()}`) into `${params.outdir}/<group>`.
- Run `pre-commit install` after cloning (`.pre-commit-config.yaml` runs prettier + editorconfig-checker + nf-core linting).
- `.nf-core.yml` lists files intentionally diverging from the nf-core template (under `lint.files_unchanged` / `lint.files_exist`) — adding files in those paths re-enables the lint check.
- `is_nfcore: false` — this pipeline borrows the template but is not under the `nf-core/` org, so don't add `nf-core/` paths or AWS test workflows.
